# FaultLens

### Sensor-Fault-Aware Predictive Maintenance for Industrial Machines

**"Know whether the machine is failing, or the sensor is lying."**

FaultLens is a predictive-maintenance software prototype developed for **INTELLATHON '26 — Industry 5.0 & Automation**. It explores how faulty sensor readings can mislead industrial machine-health monitoring and Remaining Useful Life (RUL) estimation.

Instead of treating every unusual reading as machine degradation, FaultLens analyses relationships between sensor channels, identifies suspicious readings, compares RUL estimates, and recommends an appropriate next action for human review.

## Live Prototype

**Try FaultLens:** https://fault-lens-monitor.lovable.app

> FaultLens is a software prototype. It is not connected to live industrial machinery.

## Key Features

- **Sensor Fault Injection:** Simulate frozen, spike, bias, and drift faults in sensor readings.
- **Sensor Anomaly Detection:** Use sensor reconstruction residuals to flag suspicious channels.
- **Fault Isolation:** Estimate suspicious sensor values using relationships between sensor channels.
- **RUL Estimation:** Compare Remaining Useful Life estimates for clean, corrupted, and handled sensor data.
- **Evaluation Dashboard:** Explore fault-detection metrics, false alarms, and RUL estimation errors.
- **Action Recommendations:** Recommend monitoring, sensor verification, machine inspection, or manual review based on the prototype's detection logic.
- **Interactive Visualisation:** Explore simulated machine trajectories, injected faults, sensor behaviour, and model outputs.

## How It Works

1. **Generate or Load Data** — Use synthetic engine data or upload a supported FD001-format dataset.
2. **Inject Sensor Faults** — Simulate a fault affecting a selected sensor.
3. **Detect Anomalies** — Compare observed readings with reconstructed sensor values.
4. **Estimate and Compare RUL** — Examine estimates from clean, corrupted, and handled data.
5. **Recommend an Action** — Present a suggested response for human review.
6. **Evaluate Performance** — Inspect the available detection and RUL error metrics.

## Getting Started

### Prerequisites

- [Bun](https://bun.sh/) installed
- Git installed
- Visual Studio Code or another code editor

### Installation

Clone the repository and navigate into the project directory:

```bash
git clone https://github.com/Subhiksha86/Fault-Lens-monitor.git
cd Fault-Lens-monitor
```

Install dependencies:

```bash
bun install
```

Start the local development server:

```bash
bun run dev
```

Open the local URL displayed in the terminal.

## Dataset and Evaluation

FaultLens currently supports synthetic engine data and a parser for data in the NASA C-MAPSS FD001 training-file format.

**Important limitations:**

- Injected sensor faults are generated by the project and are not official NASA sensor-fault labels.
- Synthetic-data results demonstrate prototype behaviour; they do not establish real-world industrial performance.
- RUL evaluation depends on the validity of the reference labels used.
- Standard C-MAPSS test trajectories are truncated and use separate RUL reference values. They must not be evaluated as complete run-to-failure trajectories without appropriate label handling.
- Detection thresholds and action recommendations are prototype heuristics and may require human verification.
- The application has not been established as a replacement for industrial safety systems or expert judgment.
